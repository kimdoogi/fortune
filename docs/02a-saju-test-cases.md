# 02a. 사주 테스트 케이스 명세

상태: ✅ 기대값 129/129건 (2026-11-24). `fortune-engine`이 전부 통과. 남은 것: 다른 만세력과 교차 검증, §5 계산 예시

- 테스트 데이터: [`tests/fixtures/saju/cases.json`](../tests/fixtures/saju/cases.json)
- 생성 스크립트와 KASI 원자료: [`tools/saju-fixtures/`](../tools/saju-fixtures/) (`python3 tools/saju-fixtures/build.py build OUT.json`으로 같은 파일을 다시 만들 수 있음)

[02 사주 계산 규칙](02-saju-rules.md)을 코드로 옮겼을 때 맞게 됐는지 확인하는 테스트 데이터의 명세다. `fortune-engine`은 이 케이스를 전부 통과해야 M1을 끝낼 수 있다 ([14](14-milestones.md#m1-기반)).

## 1. 원칙
- **기대값은 우리 코드로 만들지 않는다.** 한국천문연구원(KASI) 자료가 1차 기준이다.
- **다른 만세력 1곳과 교차 검증한다.** 단, 규칙(30분 경계, 자시 시작에 일주 변경)이 같은 곳이어야 한다 ⬜ 어디로 할지.
- 두 출처가 다르면 케이스의 `notes`에 원인을 적고, 어느 쪽을 따를지 정한 뒤 기록한다.
- 경계 케이스는 KASI 절기 시각을 먼저 확인하고, 그 시각의 **2분 전과 2분 후**를 입력으로 쓴다. KASI는 분 단위로 반올림해 발표하므로 1분 차이는 실제 순간과 어긋날 수 있다.
- fixture는 `tests/fixtures/saju/cases.json` 한 파일에 둔다. 케이스마다 출처와 확인 날짜를 남긴다.

## 2. 테스트가 확인하는 규칙

| 규칙 | 내용 | 근거 |
|---|---|---|
| 연주 | 입춘 시각(절대 시각)을 지나야 해가 바뀐다 | [02 §2](02-saju-rules.md#2-기둥-세우는-규칙) |
| 월주 | 12절(입춘, 경칩, 청명, 입하, 망종, 소서, 입추, 백로, 한로, 입동, 대설, 소한) 시각을 지나야 달이 바뀐다 | [02 §2](02-saju-rules.md#2-기둥-세우는-규칙) |
| 기준시 | 출생 시계 시각 → 그 시기 표준시·서머타임을 빼서 UTC로 → **UTC+8:30**으로 환산 | D-032, D-034 |
| 시주 경계 | 기준시 정시 홀수시. 지금 한국 표준시로는 **23:30, 01:30, 03:30 …** | D-034 |
| 일주 경계 | 자시가 시작되는 **기준시 23:00**(지금 한국 표준시 23:30)에 다음 날로 넘어간다 | D-033 |
| 지원 범위 | 출생 1920-01-01부터, 일진은 2050-12-31까지 | D-035 |
| 시간 모름 | 시주는 `null`. 일주는 달력 날짜 그대로 | [02 §4](02-saju-rules.md#4-시간-모름-처리) |

**기준시 예시**
- 2000년 출생, 시계 23:40 (UTC+9) → 기준시 23:10 → 자시, 다음 날 일주
- 1958년 출생, 시계 01:10 (그때 표준시가 UTC+8:30) → 기준시 01:10 → 축시. "한국 표준시에서 30분 빼기"를 무조건 적용하면 자시로 잘못 나온다
- 1987년 7월 출생, 시계 10:15 (서머타임 UTC+10) → 기준시 08:45 → 진시

## 4. fixture 형식

실제 파일의 B-02:

```json
{
  "id": "B-02",
  "category": "ipchun",
  "input": { "calendar": "solar", "date": "2005-02-04", "time": "02:45",
             "isLeapMonth": false, "hourUnknown": false },
  "expected": {
    "referenceTime": "2005-02-04T02:15+08:30",
    "solarDate": "2005-02-04",
    "pillars": { "year": "을유", "month": "무인", "day": "기미", "hour": "을축" },
    "flags": { "solarTermDay": false, "ambiguousTime": false },
    "error": null
  },
  "check": "2005 입춘 +2분",
  "basis": ["KASI 2005 입춘 02월04일 02시43분", "KASI 2005 경칩 03월05일 20시45분", "KASI 일진 2005-02-04"],
  "sources": ["KASI astro.kasi.re.kr (월력요항 24절기, 음양력 변환 /life/solc, /life/lunc)",
              "연·월·시 간지: 60갑자 순환, 월두법, 시두법"],
  "crossChecked": null,
  "checkedAt": "2026-11-24"
}
```

- `crossChecked`: 다른 만세력으로 확인하면 출처를 적는다

- `expected.error`: 입력이 잘못된 케이스에서만 오류 코드를 넣는다 (예: `OUT_OF_RANGE`, `INVALID_DATE`, `NO_SUCH_LEAP_MONTH`, `NONEXISTENT_TIME`)
- 간지는 한글 두 글자로 쓴다 (예: `갑자`)

## 6. 경계 처리 규칙 (기대값에 영향)
- ✅ **시간 모름 + 절기 당일**(J-03, J-04): 그날 정오(12:00, 시계 시각)로 계산한다. 결과에 `solarTermDay: true`를 넣고 화면에 "절기가 바뀌는 날이라 태어난 시간에 따라 달라질 수 있어요"를 표시한다 (D-036)
- ✅ **존재하지 않는 시각**(F-05, 서머타임이 시작되며 건너뛴 시간): 입력 오류 `NONEXISTENT_TIME`으로 막고 다시 입력받는다 (D-037)
- ✅ **두 번 있는 시각**(F-06, 서머타임이 끝나며 반복된 시간): 서머타임이 적용된 앞쪽 시각으로 계산하고, 화면에 "서머타임이 끝난 시간대라 앞쪽 시각으로 계산했어요"를 표시한다. 결과에 `ambiguousTime: true` (D-038)
- [ ] 교차 검증에 쓸 만세력 ⬜

## 7. 기대값을 채운 방법 (2026-11-24)
API 인증키 없이 KASI 웹사이트(astro.kasi.re.kr)의 공개 자료만 썼다.

| 값 | 출처 |
|---|---|
| 일주 (일진) | KASI 음양력 변환 (양력→음력 조회 결과의 일진) |
| 음력 → 양력, 윤달 여부 | KASI 음양력 변환 (음력→양력) |
| 절기 시각 (B, C, J, D-10) | KASI 월력요항 2004~2017년 24절기 표 |
| 연주 | 60갑자 순환 + 입춘 시각 판정 |
| 월주 | 12절 판정 + 월두법 |
| 시주 | 기준시의 시 + 시두법 (일간 기준) |

- 절기와 하루 이상 떨어진 날짜(A, D, E, F, G, H, I 등)는 KASI 공개 자료가 없는 해라도 월이 바뀌지 않으므로, **천문 계산(Meeus 근사식)**으로 어느 달인지만 판정했다. 이 계산은 KASI 2004~2017년 공식 시각 168개와 비교해 최대 13분, 평균 3분 차이였고, 판정한 날짜는 모두 절기와 6시간 이상 떨어져 있다.
- **교차 확인 결과**
  - KASI 일진 218일치 = 율리우스일 계산으로 구한 일진, 전부 일치
  - 연주가 KASI 세차와 다른 경우는 7건이고, 전부 "입춘과 설날 사이" 날짜라 예상한 차이다 (KASI 세차는 음력 설 기준)
- ⚠️ KASI 월건은 음력 달 기준이라 사주의 월주(절기 기준)와 다르다. 월주는 대조에 쓰지 않았다.
- 케이스마다 `basis`에 판정 근거를 적었다 (어떤 KASI 시각을 썼는지, 천문 계산으로 판정했는지).

- 표준시·서머타임은 IANA tz database 기록을 쓴다 (§3)
