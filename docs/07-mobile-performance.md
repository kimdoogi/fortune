# 07. 모바일 성능 한도

상태: ✅ 확정 (2026-11-24, D-059). 수치는 M1 실측 후 조정할 수 있다

수치가 정해져야 아트와 코드가 기준을 갖는다. 모든 수치는 **목표 기기에서 실제 측정**으로 검증한다.

## 1. 목표 기기
| 등급 | 기준 기기 | 목표 FPS |
|---|---|---|
| 최소 지원 | 갤럭시 A 시리즈 중급(2022년 이후 출시, A33·A53급), 아이폰 11 | 30 |
| 권장 | 갤럭시 S22, 아이폰 13 이상 | 60 |

- ✅ 지원 브라우저: iOS Safari 17 이상, Android Chrome·삼성 인터넷 최신 2개 버전, **카카오톡 인앱 브라우저** (공유 링크로 많이 들어옴). 인스타그램 인앱 브라우저는 되는 만큼 지원
- ✅ **WebGL2가 필요하다.** 지원하지 않으면 거리·점집에 들어가지 않고 안내한다 ([F01](features/F01-map.md)). WebGL1 대체 경로는 만들지 않는다
- ✅ 세로 화면 고정. 가로로 돌리면 "세로로 돌려 주세요" 안내

## 2. 용량과 로딩
| 항목 | 한도 (gzip 기준) |
|---|---|
| 첫 화면(지도)까지 다운로드 | 1MB 이하 (Preact + SVG 지도, 3D 엔진 없음) |
| 3D 엔진 + 공통 모델 생성 코드 | 추가 1.5MB 이하 (지도에 있는 동안 미리 불러옴) |
| 첫 화면 표시 시간 (4G, 최소 지원 기기) | 2초 이내 |
| 지도 → 거리 진입 | 3초 이내 |
| 거리 → 점집 내부 | 2초 이내 ([F04](features/F04-shop-enter.md)) |

## 3. 렌더링 한도 (화면당)
| 항목 | 거리 | 점집 내부 |
|---|---|---|
| 드로우콜 | 100 이하 | 60 이하 |
| 삼각형 수 (화면 전체) | 15만 이하 | 8만 이하 |
| 캐릭터 1명 | 3,000 삼각형 이하 | 〃 (점술가 NPC는 5,000 이하) |
| 텍스처 최대 크기 | 1024×1024 | 〃 |
| 동시에 그리는 다른 유저 | 최대 29명 (D-011). §4 규칙으로 줄일 수 있음 | — |
| 실시간 그림자 | 끔. 캐릭터 발밑에 원형 가짜 그림자 | 〃 |
| 재질 | `MeshLambertMaterial` + 버텍스 컬러 위주. 무거운 PBR 재질 쓰지 않음 | 〃 |

## 4. 런타임 생성과 최적화
3D는 모델 파일 없이 three.js 코드로 만든다 (D-029). 메쉬·텍스처 파일 압축은 필요 없고, 대신 아래를 지킨다.
- ✅ 같은 모양은 지오메트리를 한 번만 만들어 재사용한다 (다른 유저 29명이 같은 기본 몸통을 공유)
- ✅ 반복되는 물체(나무, 등불, 기와 등)는 InstancedMesh로 그린다
- ✅ 움직이지 않는 배경은 생성 후 지오메트리를 합쳐 드로우콜을 줄인다
- ✅ 생성 시간 한도 (최소 지원 기기): 거리 장면 500ms 이하, 점집 내부 300ms 이하
- ✅ 텍스처 대신 버텍스 컬러·단색 재질을 쓴다. 텍스처는 SVG를 래스터화한 것만
- ✅ 3D 안에 쓰는 SVG(D-030)는 캔버스 텍스처로 **한 번만** 래스터화하고 캐시한다
- ✅ 멀리 있는 유저: 8m 밖은 이름표를 숨기고, 15m 밖은 캐릭터를 숨긴다. 8m 밖 캐릭터의 애니메이션은 초당 10번만 갱신
- ✅ **자동 품질 조절:** 평균 FPS가 목표의 80% 아래로 5초 이어지면 한 단계씩 낮춘다
  1. 화면 해상도 비율 2 → 1.5 → 1
  2. 파티클·연출 효과 끔
  3. 먼 유저부터 숨김 (최소 10명은 보임)
- ✅ 설정에 "가볍게 보기" 토글: 위 3단계를 처음부터 켠다

## 5. 메모리
- ✅ 목표: JS 힙 + GPU 메모리 합계 300MB 이하 (iOS Safari가 탭을 강제로 닫지 않게)
- ✅ 화면을 바꿀 때 이전 화면의 지오메트리·재질·텍스처를 `dispose()` 한다. 예외: 점집 내부에 있는 동안 거리 장면은 최대 5분 유지 ([F04](features/F04-shop-enter.md))
- ✅ 공통 지오메트리(캐릭터 몸통 등)는 앱이 켜져 있는 동안 계속 둔다

## 6. 측정 방법
- ✅ 도구: Android는 Chrome 원격 디버깅, iOS는 Safari 웹 인스펙터. three.js `renderer.info`로 드로우콜·삼각형 수 확인
- ✅ 앱 안 디버그 오버레이 (`?debug=1`): FPS, 드로우콜, 삼각형, 메모리
- ✅ 측정 시나리오: 거리에 테스트 봇 29명을 걷게 하고 2분간 평균·최저 FPS 기록
- ✅ 마일스톤(M1~M5)마다 최소 지원 기기 2대(갤럭시 A, 아이폰 11) 결과를 `docs/perf/YYYY-MM-DD.md`에 남긴다
