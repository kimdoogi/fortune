# F09. 자유질문

- 상태: ✅ 확정 (2026-11-24). 의미표 같은 콘텐츠는 별도로 채운다
- 관련 문서: [04 §6](../04-llm-spec.md#6-분류-호출-자유질문--꿈-내용), [03 자유질문](../03-tarot-and-other-readings.md#자유질문-유료-d-006), [10](../10-payments-currency.md)
- 마일스톤: M4
- 붙일 수 있는 상품: `tarot_three`, `obanggi`. 무료 (D-057)

## 목적
"그 사람이 연락할까요?"처럼 내 질문을 붙여서 점을 본다.

## 사용자 흐름
1. 세 장 스프레드(F06) 또는 오방기(F07)에서 "질문 붙이기"
2. 질문을 쓴다 (100자 이하, D-027)
3. "이 질문으로 볼게요" → 서버 검사
4. 통과하면 원래 점 흐름으로 돌아간다

## 입력
| 항목 | 타입 | 검증 |
|---|---|---|
| 질문 | 텍스트 | 100자 이하, 비어 있으면 안 됨 |

- 검사: `POST /api/readings/check { shop, text }` → `{ checkId(questionId), ok, reason?, category }` (F08과 같은 API)

## 출력
- 통과: `questionId`, 분류된 카테고리. **질문을 붙이면 카테고리 고르기 단계는 건너뛰고 분류 결과를 쓴다** (D-056)
- 차단: 이유별 안내 문구

## 처리 규칙
- 검사 절차와 `risk`별 처리는 F08과 같다 ([04 §6](../04-llm-spec.md#6-분류-호출-자유질문--꿈-내용))
- `medical`, `legal`, `investment`면 통과시키되 해석 입력에 `caution`을 넣는다
- 질문은 해석 입력의 `question`에만 들어가고, 시스템 프롬프트는 이것을 데이터로만 다룬다 ([04 §7](../04-llm-spec.md#7-안전-규칙과-프롬프트-공격-대응))
- 질문 원문은 결과와 함께 저장한다 (다시 보기에 필요). 로그에는 남기지 않는다

## 예외 상황
| 상황 | 처리 |
|---|---|
| 차단 | "질문 없이 볼까요?" 선택지 |
| 프롬프트 공격 문장 ("규칙 무시해") | 그대로 데이터로 넘어간다. 평가 샘플에 포함해 무시되는지 확인 |

## 완료 기준
- [ ] 차단된 질문은 해석 호출로 넘어가지 않는다
- [ ] 프롬프트 공격 샘플 5개 이상에서 캐릭터·규칙이 유지된다
- [ ] 투자·건강 질문에 단정 표현이 없다

## 하지 않는 것
- 사주 정밀·꿈해몽에 질문 붙이기
- 결과에 이어서 추가 질문하기 (대화형)
