# F10. 결과 저장 / 다시 보기 (점 기록)

- 상태: ✅ 확정 (2026-11-24). 의미표 같은 콘텐츠는 별도로 채운다
- 관련 문서: [09 §2](../09-backend-data.md#2-데이터-구조-초안), [03 결과 고정](../03-tarot-and-other-readings.md#공통-결과-고정-규칙)
- 마일스톤: M2

## 목적
내가 본 점을 다시 꺼내 본다.

## 사용자 흐름
1. 지도(F01)의 "점 기록" 버튼
2. 날짜순 목록: 점집 아이콘, 상품 이름, 날짜, 한 줄 요약
3. 하나를 누르면 결과 화면(S5)이 열린다. 한 글자씩 연출 없이 바로 보여준다
4. 결과를 왼쪽으로 밀면 삭제. "삭제하면 되돌릴 수 없어요" 확인 후 지운다 (D-055)

## 입력
- 목록: `GET /api/readings?cursor=` (20개씩)
- 하나: `GET /api/readings/:id`
- 삭제: `DELETE /api/readings/:id`

## 출력
- 목록 항목: `{ id, shop, product, createdAt, summary }`
- 하나: 저장된 결과 JSON 전체 + 당시 입력(카드, 깃발, 질문, 꿈 내용, 사주판)

## 처리 규칙
- 결과는 `readings`에 저장된 것만 보여준다. **다시 보기는 LLM을 부르지 않는다**
- 저장하는 것: 상품, seed, 입력 JSON, 출력 JSON, 프롬프트 버전, 생성 시각 ([09](../09-backend-data.md#2-데이터-구조-초안))
- 실패한 결과는 저장하지 않는다 ([04 §9](../04-llm-spec.md#9-실패-처리))
- 오늘의 운세는 기록에 남기지 않는다 (F13)
- 보관 기간: 마지막 접속 후 **2년**이 지나면 계정과 기록을 함께 지운다 (D-055, [09 §4](../09-backend-data.md#4-개인정보)). 개인정보처리방침에 적는다
- 다른 사람의 결과 ID로 요청하면 404 (존재 여부도 알리지 않음)

## 예외 상황
| 상황 | 처리 |
|---|---|
| 기록 없음 | 점집으로 안내하는 빈 화면 |
| 삭제한 결과를 다시 보면 | seed가 같아 같은 카드·깃발이 나오지만 풀이는 새로 생성된다 (하루 30회 상한에 포함) |

## 완료 기준
- [ ] 다시 보기 요청에서 LLM 호출이 0건
- [ ] 다른 사용자의 결과를 볼 수 없다
- [ ] 목록이 100개 이상이어도 첫 화면이 1초 안에 뜬다 (20개씩 불러오기)

## 하지 않는 것
- 결과 검색, 필터
- 기록을 다른 기기로 옮기기 (로그인 이후)
