# F12. 복채 지급 / 사용

- 상태: ⏸ **MVP 제외 (D-057).** MVP에는 복채가 없다. 유료화할 때 이 명세로 다시 시작한다
- 관련 문서: [10](../10-payments-currency.md), [09 §2](../09-backend-data.md#2-데이터-구조-초안)
- 마일스톤: M6 (유료화)

## 목적
무료로 받은 복채로 점을 본다. LLM 비용과 이용 빈도를 조절하는 장치이고, 나중에 PG만 붙이면 유료 충전이 된다 (D-019).

## 사용자 흐름
1. 화면 위에 늘 잔액 표시 (엽전 아이콘 + 숫자)
2. 받는 때: 첫 방문 30냥, 매일 첫 접속 10냥, 공유 5냥 (D-025). 받을 때마다 엽전이 떨어지는 연출
3. 쓰는 때: 유료 점을 고르면 "N냥을 낼까요? (남은 복채 M냥)" 확인
4. 잔액을 누르면 내역: 받은 것·쓴 것·돌려받은 것
5. 모자라면 "복채가 모자라요" 화면: 내일 출석, 공유로 받을 수 있다고 안내

## 입력
- 받기: `POST /api/wallet/claim { reason: "first_visit" | "daily" | "share", requestId }`
- 잔액·내역: `GET /api/wallet?cursor=`
- 쓰기: 각 점 요청 안에서 서버가 처리 (별도 API 없음)

## 출력
- `{ balance, cap: 100, entries: [{ delta, reason, refId, createdAt }] }`

## 처리 규칙
- **잔액 = 원장(`wallet_ledger`) 합계.** 원장은 추가만 하고 고치거나 지우지 않는다
- 원장 항목: `delta`, `reason`(`first_visit`, `daily`, `share`, `reading`, `unlock`, `refund`, `admin`), `refId`, `source`(`free` | `paid`), `requestId`
- **보유 상한 100냥:** 지급 후 잔액이 100을 넘으면 100까지만 지급한다. 상한이면 "복채 주머니가 가득 찼어요"
- **출석:** "하루"는 한국 시간 자정 기준. 첫 접속(F01 진입) 때 자동 지급
- **차감:** 잔액 확인 + 차감 + `readings(pending)` 저장을 한 트랜잭션으로 ([15 §3](../15-infrastructure.md#3-풀이-요청-흐름))
- **환원:** 해석 실패면 같은 금액을 `refund`로 넣는다
- **중복 방지:** `requestId`가 같은 요청은 한 번만 처리하고 같은 결과를 돌려준다
- 하루 최대 사용량은 따로 두지 않는다. 하루에 받을 수 있는 복채가 최대 15냥(출석 10 + 공유 5)이라 그 자체가 제한이다. 대신 LLM 호출 안전장치로 사용자당 하루 30회 상한을 둔다 ([04 §10](../04-llm-spec.md#10-비용-관리))
- 서버 시각만 믿는다 (기기 시계를 바꿔도 출석이 다시 되지 않음)

## 예외 상황
| 상황 | 처리 |
|---|---|
| 같은 차감 요청이 두 번 | 한 번만 차감 |
| 차감 후 해석 실패 | 자동 환원 + "복채는 돌려드렸어요" |
| 동시에 두 점을 요청 | 트랜잭션으로 잔액 음수 방지 |

## 완료 기준
- [ ] 어떤 순서로 요청해도 잔액이 음수가 되지 않는다 (동시 요청 테스트)
- [ ] 원장 합계와 표시 잔액이 항상 같다
- [ ] 출석·공유가 하루 1번씩만 들어온다 (자정 경계 테스트)
- [ ] 상한 100을 넘지 않는다

## 하지 않는 것
- 유료 충전 (M6)
- 복채 선물하기, 다른 사람에게 보내기
- 연속 출석 보너스 (MVP 이후)
