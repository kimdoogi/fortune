# F15. 이어 묻기 (풀이에 이어 질문하기)

- 상태: ✅ 확정 (2026-11-25, D-071)
- 관련 문서: [04 §13](../04-llm-spec.md#13-이어-묻기-호출-followup), [04a 이어 묻기](../04a-persona-prompts.md#이어-묻기-followup-v1), [09](../09-backend-data.md), [F10](F10-history.md)
- 마일스톤: M2
- 붙일 수 있는 결과: 저장된 모든 풀이 (`saju_full`, `tarot_one`, `tarot_three`, `obanggi`, `dream`). 오늘의 운세(`daily`)는 저장하지 않아 제외. 무료 (D-057)

## 목적
풀이를 읽고 "그럼 그 사람이 먼저 연락할까요?", "올해 이직은요?"처럼 바로 이어서 묻는다. 점술가가 같은 말투로, 이미 나온 카드·깃발·사주 안에서 답한다.

## 사용자 흐름
1. 결과 화면(새로 본 결과, 다시 보기 모두) 맨 아래에 "더 물어보기" 칸이 있다. 남은 횟수가 보인다 ("2번 더 물어볼 수 있어요")
2. 질문을 쓴다 (100자 이하, 글자 수 표시)
3. 보내면 점술가가 생각하는 연출 뒤 답이 한 글자씩 나온다 (말풍선)
4. 앞의 질문과 답이 대화처럼 쌓인다. 다시 보기에서도 그대로 보인다

## 입력
| 항목 | 타입 | 검증 |
|---|---|---|
| 질문 | 텍스트 | 1~100자 (D-027), 개인정보 패턴·금칙어 없음 |

- `POST /api/readings/:id/followups { question, requestId }`

## 출력
- `{ followup: { id, question, answer, createdAt }, followupsLeft, todayCallsLeft }`
- `GET /api/readings/:id` 결과에 `followups[]`, `followupsLeft`가 함께 온다

## 처리 규칙
- 같이 본 풀이(F16)는 문답을 두 사람이 함께 본다. 한도는 사람마다 3번 (D-091)
- **한 풀이에 3번까지** 물을 수 있다. 4번째부터는 "이 풀이에는 세 번까지 물을 수 있어요. 새로 점을 봐요" 안내
- 1차 필터(코드): 길이, 개인정보 패턴, 금칙어 — 걸리면 LLM 호출 없이 안내 (F08과 같은 문구 규칙)
- **위험 검사와 답을 한 번의 호출로 한다** (D-071). 구조화 출력 `{ risk, answer }`. 분류 호출을 따로 부르지 않아 비용·지연이 절반
  - `self_harm` → 답을 버리고 위기 안내 화면 (04a). 저장하지 않는다
  - `sexual`, `violence` → 답을 버리고 점술가 말투 안내 ("그 이야기는 여기서 할 수 없구려"). 저장하지 않는다
  - `other` → 모델이 답을 썼으면 그대로 보여 준다 (일상 질문을 `other`로 잘못 고르는 오탐 방지, 2026-11-25). 답이 비었을 때만 차단 안내
  - 프롬프트는 "이직·연애·시험·돈 모으기 같은 일상 고민은 모두 none, 애매하면 none"으로 못 박는다 (followup v2)
  - `medical`, `legal`, `investment` → 답은 주되 단정하지 않고 전문가를 권한다 (프롬프트 규칙)
- 답은 **이미 나온 점과 facts 안에서만**. 새 카드·깃발을 뽑지 않는다. 동떨어진 질문이면 새 점을 보라고 권한다
- 하루 30회 상한에 1회로 센다. 실패(LLM 오류)도 센다 (04 §9와 같음)
- 같은 `requestId`는 한 번만 처리한다
- **캐시:** 원래 풀이의 입력·출력과 앞선 문답을 같은 순서·같은 바이트로 보내 앞부분이 프롬프트 캐시에서 읽히게 한다 ([04 §13](../04-llm-spec.md#13-이어-묻기-호출-followup))
- 질문 원문과 답은 결과에 딸려 저장한다 (다시 보기용). 결과를 지우면 함께 지운다. 로그에는 남기지 않는다

## 예외 상황
| 상황 | 처리 |
|---|---|
| 3번 다 씀 | 입력 칸 대신 "새로 점 보기" 안내 |
| 하루 상한 | 점술가 말투 `DAILY_LIMIT` 안내 |
| LLM 실패 | 대체 문장, 저장 안 함, 다시 시도 가능 |
| 위험·차단 | 위 처리 규칙 |

## 완료 기준
- [ ] 두 번째 이어 묻기부터 `cache_read_input_tokens`가 0보다 크다 (앞 문맥이 캐시에서 읽힌다)
- [ ] 답에 새 카드·깃발이 나오지 않는다 (평가 샘플)
- [ ] 위험 질문은 저장되지 않고 위기 안내·차단 안내가 뜬다
- [ ] 일상 질문(이직·연애·시험 등)이 차단되지 않는다 (오탐 0건)
- [ ] 다시 보기에 문답이 그대로 나온다

## 하지 않는 것
- 3번을 넘는 대화, 점술가와 자유 잡담
- 이어 묻기로 새 카드·깃발 뽑기
- 오늘의 운세에 이어 묻기
