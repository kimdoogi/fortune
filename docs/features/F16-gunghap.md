# F16. 궁합 (둘이 같이 보기)

- 상태: ✅ 확정 (2026-11-25, D-089)
- 관련 문서: [02 §5-9 궁합 계산](../02-saju-rules.md#5-9-궁합-d-089), [04 §4](../04-llm-spec.md#4-상품과-결과-길이-d-043-보통), [04a 상품별 지시](../04a-persona-prompts.md#상품별-지시), [06 §5](../06-world-and-scenes.md#5-멀티플레이-표시), [09 §3](../09-backend-data.md#3-api-목록-초안), [15 §4](../15-infrastructure.md#4-멀티플레이)
- 마일스톤: M3 (멀티플레이를 먼저 둘만의 방으로 연다)
- 상품: `gunghap` (사주집, 청운 선생). 무료, 하루 30회 상한에는 **풀이를 연 사람 1회**만 센다

## 목적
친구·연인·가족에게 링크를 보내 **같이** 점집 거리로 들어가 서로 걷는 모습을 보고, 나란히 앉아 청운 선생에게 둘의 궁합을 듣는다. 혼자 보는 점과 달리 "같이 놀러 가는" 경험을 만든다.

## 사용자 흐름
1. **초대 만들기 (A):** 사주집 안 메뉴 "궁합 — 둘이 같이 보기" → 동의 안내("궁합을 보면 두 사람의 띠·타고난 기운과 풀이가 서로에게 보여요. 생년월일과 태어난 시간은 보이지 않아요") → 초대 링크 생성 → 공유(휴대폰 공유 창, 안 되면 링크 복사)
2. A는 바로 **둘만의 사주집 거리**로 나간다. "친구가 들어오면 거리에 나타나요"
3. **링크 열기 (B):** `https://jumjip.app/?g=<초대 코드>` → 처음이면 프로필부터 만든다(F02) → "○○님이 궁합을 보자고 불렀어요" + 같은 동의 안내 → "같이 들어가기"
4. **같이 걷기:** 둘이 같은 거리에 있고 서로 걷는 모습이 보인다. 상대 머리 위에 닉네임. 이모트·정해진 문장은 기존 마을 규칙(06 §5) 그대로
5. **같이 들어가기:** 둘 다 문 앞(1.6m 안)에 서면 "같이 들어가기" 버튼이 둘 모두에게 뜬다. 누가 눌러도 둘 다 함께 페이드 → 점집 안. 한 사람만 문 앞이면 "○○님을 기다리는 중"
6. **점집 안:** 둘이 상 앞 방석에 나란히 앉는다(왼쪽 = 초대한 사람). 청운 선생이 "어떤 사이요?"를 묻고, 누구든 **관계**를 고른다: 연인 · 썸 · 친구 · 가족 · 동료. 고른 것은 상대 화면에도 바로 보인다
7. 고르자마자 풀이를 만들고, **둘에게 같은 결과**가 동시에 뜬다: 궁합 판(두 사람 띠·기운, 점수 0~100과 등급, 좋은 점·부딪히는 점 표시) + 섹션
8. 결과는 각자의 점 기록(F10)에 남고, 각자 이어 묻기(F15) 3번을 쓸 수 있다

## 입력
- 초대 만들기: `POST /api/gunghap/invites { consent: true }` → `{ code, url, expiresAt }`
- 초대 보기: `GET /api/gunghap/invites/:code` → `{ hostNickname, status, role: "host" | "guest" | "none", full }`
- 참여: `POST /api/gunghap/invites/:code/join { consent: true }`
- 실시간 방 토큰: `GET /api/ws-token?room=pair:<code>` (초대한 사람·참여한 사람만)
- 풀이: `POST /api/gunghap/invites/:code/reading { relation, requestId }` → 만든 사람에게 `ReadingResult`. 상대에게는 방으로 `result_ready`를 알리고, 상대는 `GET /api/gunghap/invites/:code/result`로 자기 기록을 받는다

## 출력
- `ReadingResult` (`shop: "saju"`, `product: "gunghap"`). `visual = { shop: "saju", gunghap: { score, label, relation, a: Person, b: Person, factors: { name, good }[] } }`, `Person = { nickname, zodiac, dayStem, element }`
- 섹션: `overall`(총평), `chemistry`(성격 궁합), `strengths`(잘 맞는 점), `friction`(부딪히는 점), `tips`(둘이 같이 할 일)

## 처리 규칙
- **계산은 코드** ([02 §5-9](../02-saju-rules.md#5-9-궁합-d-089)): 일간 오행 관계, 일간 천간합, 띠(연지) 육합·삼합·충·원진, 일지 합충, 서로의 용신 보완 → 점수와 요인. LLM은 요인 문장만 풀어 준다
- **초대 코드:** 10자 무작위(헷갈리는 글자 뺀 영숫자). 만든 뒤 30분 안에 참여하지 않으면 만료, 참여 뒤에는 3시간 유효. 한 초대에 손님은 한 명. 자기 초대에는 참여할 수 없다
- **결과 고정:** 초대 하나에 풀이 하나 (`seed_key = gunghap:<code>`). 두 사람 각자 기록 한 줄씩(같은 내용) 저장해 각자 지울 수 있다
- **LLM 입력:** 두 사람의 닉네임·성별·나이대와 계산된 간지·요인만 (D-051). 생년월일 원본은 보내지 않는다
- **실시간 방:** `pair:<code>` Durable Object, 정원 2명. 이동은 목적지만 보내고 각자 경로를 재생(06 §5). 방 메시지: `move`, `emote`, `chat`, `go_inside`(같이 들어가기), `pick`(관계 고름), 서버 → `result_ready`
- 상대가 나가면 "○○님이 나갔어요" 표시. 다시 같은 링크로 들어오면 이어진다(유효 시간 안)
- 결과 하단 "재미로 보는 풀이예요"는 코드가 붙인다

## 예외 상황
| 상황 | 처리 |
|---|---|
| 초대 만료·없는 코드 | "초대가 끝났소. 친구에게 새 링크를 받아 주시오" + 지도 가기 |
| 이미 다른 사람이 참여 | "이미 다른 분이 같이 보고 있소" |
| 내 초대를 내가 열기 | 초대한 사람으로 방에 들어간다 |
| 프로필 없음 (B) | 프로필 만들기(F02) 뒤 초대 화면으로 돌아온다 |
| 실시간 연결 끊김 | 3초 뒤 다시 연결(최대 5번). 그동안 상대는 멈춰 보인다. 점 보기는 계속 가능 |
| LLM 실패 | 대체 문장, 다시 시도 (04 §9). 둘 다에게 실패를 알린다 |
| 하루 상한 | 고른 사람에게 상한 안내. 상대가 대신 고를 수 있다 |
| 위험한 이어 묻기 | F15 그대로 |

## 완료 기준
- [ ] 두 브라우저에서 링크로 같은 방에 들어가 서로 걷는 모습이 보인다 (0.5초 안에 반영)
- [ ] 둘 다 문 앞이면 같이 들어가고, 안에서 나란히 앉는다
- [ ] 관계를 고르면 둘 다 같은 결과를 본다. 결과는 각자 기록에 남는다
- [ ] 같은 초대로 다시 들어오면 LLM을 다시 부르지 않는다
- [ ] 점집 안 드로우콜·삼각형 한도(07) 안 (캐릭터 한 명 추가)

## 하지 않는 것
- 세 명 이상 같이 보기
- 둘만의 방에서 자유 채팅 (정해진 문장·이모트만)
- 사주 없이 이름만으로 보는 궁합
